- name: Wiki-link index store lacks workspace-switch race protection
- file: /media/adam/extex/projects/thinkbrain-notes/apps/desktop/src/wikiLinks/wikiLinkIndexStore.ts
- lines: 92-178
- description: `useWikiLinkIndexStore.indexWorkspace` (lines 97-119) sets `rootPath` synchronously, then `Promise.all` reads every file, then re-checks `get().rootPath !== rootPath` before committing the index. This guards the *commit* but not the *reads*: a superseding `indexWorkspace` for a new workspace will fire its own `Promise.all`, and the two batches race against each other on the Tauri IPC bridge. Whichever finishes last wins the `set`, but the guard at line 109 only prevents stale commits — it does not cancel the in-flight reads, so a slow old-workspace read can still be running (wasting IPC and CPU) when the new workspace's reads start.

  More importantly, unlike `searchIndexStore.ts` (lines 70-110), there is **no `AbortController`** and no `indexingAbortController` sentinel. The search store aborts the previous indexing operation on a new `indexWorkspace` call and on `clearWorkspace` (lines 78, 114). The wiki-link store has neither. Consequences:
  - Rapid workspace switches (or open→close→open) leak in-flight `read_markdown_file` IPC calls that cannot be cancelled.
  - `clearWorkspace` (lines 121-127) does not abort an in-flight `indexWorkspace`, so a workspace that was just closed can still write `wikiLinkIndex`/`noteIndex` into the store *after* `clearWorkspace` reset them — the `get().rootPath === rootPath` guard in the catch block (line 115) only fires on error, and the success path's guard (line 109) passes because `rootPath` was set by the now-closed workspace's own `indexWorkspace` and `clearWorkspace` set it back to `null`... actually the guard *does* catch this since `rootPath` is now `null !== oldRootPath`. So the success path is safe, but the in-flight reads still run to completion uselessly, and there is no way to short-circuit them.

  The asymmetry with `searchIndexStore` is the core issue: the sibling store this module deliberately mirrors handles abort explicitly; this one silently drops it.

- verification: Read `apps/desktop/src/search/searchIndexStore.ts` lines 70-110 (AbortController pattern, `indexingAbortController?.abort()` on new index and on `clearWorkspace`) and compared against `wikiLinkIndexStore.ts` lines 97-127 (no abort, no controller, only a post-read `rootPath` guard). Confirmed `read_markdown_file` is invoked via `invokeNativeCommand` with no signal argument (lines 78-81), so even if an abort controller existed it would need plumbing through the native bridge.
