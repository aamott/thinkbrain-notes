  - No roving `tabindex` management: treeitems have no `tabIndex` attribute, so every item is tabbable (or none, when the inner `<button>` is the focusable element). The expected pattern is `tabindex={0}` on the active item and `tabindex={-1}` on the rest, with Arrow Up/Down moving focus, Arrow Right/Left expanding/collapsing, and Home/End jumping to first/last.

  - Disabled section buttons use `disabled={!hasSettings}` (line 78), which removes them from the tab order entirely. A disabled group label cannot be reached by keyboard users at all, so the chevron toggle (rendered only when `hasSubsections`, line 63) is also unreachable for those rows.
  - `aria-current="true"` is set on the section button (line 79) inside a `treeitem`; `aria-current` is not part of the tree pattern and is redundant/confusing alongside tree selection semantics. The tree pattern uses `aria-selected` on treeitems (or `[aria-current]` on a `link`), not on a nested button.
  - The `ModuleGroup` `<li role="treeitem" aria-expanded="true">` (line 124) is hardcoded to `aria-expanded="true"` and is not focusable (no button/tabindex), so the module group is announced as an expanded treeitem that can't be operated.
