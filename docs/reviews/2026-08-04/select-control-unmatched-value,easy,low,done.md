- description: `selected = typeof value === "string" ? value : String(value ?? "")` (line 15) is passed to `<select value={selected}>`. If `selected` is not one of `definition.options` (e.g. a migrated value, a stale persisted value after options changed, or a non-string coerced via `String()`), the browser shows the first `<option>` as visually selected but the `value` prop does not match any option. The user sees a value that is not the actual stored value, and changing the dropdown stages the first option's value — silently overwriting the mismatched stored value. There is no inline indication (e.g. an "(invalid value)" placeholder option) that the current value is outside the allowed set. Consider rendering a disabled placeholder `<option value="">(invalid: {String(value)})</option>` when `selected` is not in `options`, so the mismatch is visible and the user must consciously pick a valid option.
