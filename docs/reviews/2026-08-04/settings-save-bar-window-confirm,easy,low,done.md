- description: `handleExport` (lines 102-117) calls `window.confirm(...)` (line 106) to warn about non-portable settings before exporting. The desktop src AGENTS.md rule states "UI components must never invoke Tauri IPC directly. Route all native operations through `native/`." `window.confirm` is a browser primitive, not Tauri IPC, so it does not strictly violate that rule, but it produces a Chromium-default dialog that is visually inconsistent with the rest of the Tauri app (which uses native file dialogs via `native/dialogs` for the export itself at line 112 / `writeExportFile`). The same `native/dialogs` module that provides `pickFilePath` (used by PathControl) is the natural place for a native confirm. This is a consistency/UX issue rather than a correctness bug. Note also that `window.confirm` returns a synchronous boolean, so migrating to an async native confirm would require making `handleExport` async and awaiting the result before `writeExportFile`.
