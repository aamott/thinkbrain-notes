- description: The effect at lines 96-99 depends on `[settingsIsDirty, tabState.tabs]`. `tabState.tabs` is a new array reference whenever *any* tab action produces a new state (open/activate/close another tab, editor dirty toggle, etc.). Each such change re-runs the effect, which re-dispatches `setDirty` for the settings tab. This is NOT an infinite loop: the reducer's `setDirty` case (tabModel.ts lines 79-82) returns the same `tab` object when `tab.isDirty === action.isDirty`, and `updateTab` (lines 101-113) returns the same `state` reference when no tab changed, so `tabState.tabs` does not change again and the effect terminates. However, the effect runs redundant dispatches on every unrelated tab mutation (e.g. opening a markdown file while a settings tab is open), which is wasted work and slightly obscures the intent. The dependency on the entire `tabState.tabs` array is broader than necessary — the effect only needs to know whether a settings tab exists, not the full tabs array. Selecting a boolean `const hasSettingsTab = tabState.tabs.some(t => t.id === "settings")` and depending on `[settingsIsDirty, hasSettingsTab]` would be more precise.
