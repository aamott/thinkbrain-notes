- name: settingHighlight bus has no listener-error guard and retains module-scoped state across HMR
- file: /media/adam/extex/projects/thinkbrain-notes/apps/desktop/src/settings/settingHighlight.ts
- lines: 40-53, 67-75
- description: The highlight bus is a module-scoped singleton (`subscribers` Set at line 21, `clearTimer` at line 24, `currentHighlight` at line 18). Two edge cases:
  1. No try/catch around listener invocation in `requestSettingHighlight` (line 42) or the clear-timeout callback (line 51). If one subscriber throws, the remaining subscribers are never notified (the `for...of` loop aborts). For a UI highlight this is low-impact, but it violates the "fail loudly without breaking siblings" pattern and could mask a render-time error in `SettingsContent`'s `setHighlightKey`.
  2. The module-scoped `subscribers` Set and `clearTimer` are not cleared on hot-reload. With Vite HMR, when `settingHighlight.ts` is re-evaluated the old `subscribers` Set is replaced by a new empty one, but any subscriber that subscribed before the reload holds a closure referencing the *old* module's `subscribers` Set — its unsubscribe function removes from the old Set, not the new one, and `requestSettingHighlight` notifies the new (empty) Set. In practice this means highlights silently stop working after an HMR of this module until `SettingsContent` re-mounts. A `import.meta.hot?.dispose(...)` hook (Vite HMR API) should clear `subscribers` and `clearTimer` on dispose.
  3. `subscribeSettingHighlight` immediately invokes `listener(currentHighlight)` (line 71). If `currentHighlight` is non-null (a highlight was requested <1200ms ago) and a new `SettingsContent` mounts, it will apply a stale highlight ring to a row that the user never clicked. This is documented as intentional ("late subscriber reflects existing state"), but combined with the 1200ms timer it can produce a confusing flash on remount.
- verification: Read settingHighlight.ts in full. Confirmed no try/catch around the listener loops (lines 42, 51) and no HMR dispose hook. Confirmed `currentHighlight` is set to `null` only inside the timer callback (line 49), so a late subscriber within the 1200ms window receives the stale key.
