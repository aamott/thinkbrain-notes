- name: Unsupported-metadata diagnostics are computed but never surfaced to the user
- file: /media/adam/extex/projects/thinkbrain-notes/packages/core/src/markdown.ts

- description: `collectIndexMetadata` (lines 49-88) emits `frontmatter_metadata_unsupported_value` and `frontmatter_metadata_unsupported_list_item` warnings into the `ParsedNote.diagnostics` array whenever a frontmatter field contains a boolean, nested object, or other non-string/number value (e.g. `published: true`, `review: { owner: user }`). These diagnostics are only produced inside `parseNote`. In the desktop app `parseNote` is consumed in exactly two places: `searchService.ts` line 109 (which reads `parsed.indexMetadata` and discards `parsed.diagnostics`) and `wikiLinks/wikiLinkIndexStore.ts` line 101 (which also discards diagnostics). The UI surfaces that render frontmatter diagnostics — `panels/PropertiesPanel.tsx` line 25, `tabs/livePreview/decorate.ts` line 94, and `journal/MetadataWidgetContainer.tsx` line 100 — all call `parseFrontmatter`, not `parseNote`, so they never run `collectIndexMetadata` and cannot show these warnings. As a result a user who writes `published: true` or a nested map gets no feedback that those fields are omitted from metadata facets; the warnings are computed on every index pass and then thrown away. Either surface the unsupported-metadata warnings in a `parseNote`-based UI path (e.g. have `PropertiesPanel` use `parseNote` so its diagnostics include the metadata warnings), or document on `MetadataQuery`/the search UI that only string and number frontmatter values are faceted, so the omission is explained rather than silent.
- resolution: Deferred as out of scope. `ParsedNote.diagnostics` is the typed diagnostic surface required by this indexing story and is covered directly; changing PropertiesPanel or journal metadata UI would cross the explicit no-UI non-goal. A later UI story may choose how and where to present indexability warnings.
