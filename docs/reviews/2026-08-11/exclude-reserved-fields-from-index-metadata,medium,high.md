- name: Exclude reserved metadata fields from indexMetadata to prevent duplicate facets
- file: /media/adam/extex/projects/thinkbrain-notes/packages/core/src/markdown.ts
- lines: 46-88
- description: `collectIndexMetadata` iterates every entry of `frontmatterResult.metadata` without filtering reserved fields. `normalizeNoteMetadata` (frontmatter.ts:125-162) populates `metadata` with BOTH the reserved fields (`title`, `tags`, `aliases`, `status`, `created_at`, `updated_at`) and the passthrough of unknown fields. As a result, `tags` and `aliases` ALWAYS appear in `parsed.indexMetadata` whenever they are non-empty, and `title`/`status`/`created_at`/`updated_at` appear when present as strings. This duplicates data already surfaced through dedicated `ParsedNote` fields (`parsed.tags`, `parsed.aliases`, `parsed.metadata.title`) and dedicated columns in `NativeDocumentInput` (`title`, `tags`, `aliases` in apps/desktop/src/native/commands.ts:340-348). `searchService.buildDocumentInput` (apps/desktop/src/search/searchService.ts:104-119) sends both the dedicated fields AND `metadata: parsed.indexMetadata`, so the Rust metadata facet store (apps/desktop/src-tauri/src/commands/search/metadata.rs) receives a `tags`/`aliases` facet that mirrors the dedicated tag/alias index — producing redundant facets and double-counted values in metadata queries. The new tests do not catch this: the "flattens distinct string and number frontmatter values" test (note-parser.test.ts:104-120) uses only non-reserved keys (`project`, `rating`, `activities`, `scores`), and the original extraction test (note-parser.test.ts:11-89) asserts only `parsed.diagnostics`, never `parsed.indexMetadata`. Fix: skip keys in `RESERVED_METADATA_FIELDS` (frontmatter.ts:13-20) inside `collectIndexMetadata` — either export that set from frontmatter.ts or define a shared constant — and add a test asserting that a note with `title`, `tags`, `aliases`, `status`, `created_at`, `updated_at` plus one custom field yields `indexMetadata` containing only the custom field.
- resolution: Rejected. The dedicated title/tags/aliases columns are FTS-only and are not queried by the facet API, so storing those frontmatter keys in `document_metadata` does not double-count facets. Excluding reserved keys would violate the story's arbitrary-key requirement and make fields such as `status`, `tags`, and `aliases` impossible to facet. A core test now pins their inclusion.
