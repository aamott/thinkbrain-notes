- description: The `pub use metadata::{MetadataField, MetadataPredicate, MetadataQueryResult};` re-export (search.rs:17) omits `MetadataValue`, `MetadataFacet`, and `MetadataQuery`. `MetadataValue` is the element type of the `values: Vec<MetadataValue>` field on the re-exported `MetadataField`, and of the `value: MetadataValue` field on the re-exported `MetadataPredicate`. Because `metadata` is declared as a private `mod metadata;` (search.rs:13), the `MetadataValue` type is reachable through struct fields (so Tauri's serde layer can serialize/deserialize it) but cannot be named by any Rust code outside the `search` module tree — there is no `crate::commands::search::MetadataValue` path. This means external Rust code (e.g. a future command or test in `tests.rs` that wants to construct a `MetadataPredicate` or inspect a `MetadataQueryResult`'s facets) cannot name the value type without reaching into the private `metadata` submodule, which the compiler rejects. The focused tests in `metadata_tests.rs` work only because they are a child of `search` and can access `super::metadata::MetadataValue` as a sibling. The IPC shape itself is correct — `NativeMetadataValue = string | number` (apps/desktop/src/native/commands.ts:358) matches the untagged enum, and `NativeMetadataFacet` (commands.ts:370-373) matches `MetadataFacet`'s `key`/`values` fields — so this is an API-completeness issue, not a runtime bug. Fix: add `MetadataValue` and `MetadataFacet` to the `pub use` list (and optionally `MetadataQuery` if external construction is desired). This is a one-line change with no behavioral impact.
- resolution: Rejected for the current command boundary. Rust callers consume the public Tauri command, `MetadataPredicate`, and `MetadataQueryResult`; construction and result serialization are handled by serde. The internal value/facet/query types are intentionally kept inside the search implementation until a Rust caller requires them.
