- description: Both popouts compute `isAvailable = contribution.availability?.(context) ?? true` and emit it only as `data-panel-available={isAvailable}` on the wrapper div. The panel factory is invoked unconditionally regardless of the result. For unavailable built-ins (`tags`, `extensions`, `backlinks`), the factory itself renders an `<Unavailable>` component. So `availability` and the in-factory `Unavailable` rendering are two parallel, redundant mechanisms expressing the same concept. The `data-panel-available` attribute is not consumed by any CSS or JS (grep found only the two emit sites). This is confusing for extension authors: is `availability` supposed to suppress the panel, or is the factory responsible for its own unavailable state? Pick one model. If `availability` is canonical, the popout should skip rendering (or render a generic unavailable shell) when it returns false and factories should not embed `Unavailable`. If the factory owns unavailable state, drop `availability` from the contribution contract and the `isAvailable` registry method (or document it as advisory metadata only).
