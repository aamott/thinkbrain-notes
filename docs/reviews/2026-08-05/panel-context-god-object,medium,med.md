- description: `DesktopPanelContext` is a single "god object" that mixes left-side-only fields (`explorerProps`, `onOpenSearchResult`) with right-side-only fields (`documentContents`). Every panel factory receives the full context regardless of side, so `RightPopout` must fabricate a complete stub `explorerProps` (lines 32-42) with no-op callbacks, dummy `initialWorkspacePath: null`, `newNoteFocusRequest: 0`, and `recentWorkspacePaths: []`, plus a no-op `onOpenSearchResult`. This violates the project's fail-loudly rule: if a future right-side extension panel accidentally reads `context.explorerProps` or calls `context.onOpenSearchResult`, it will silently do nothing instead of failing. The stub also misrepresents state (e.g. `recentWorkspacePaths: []` is not the real recent list). The core `PanelContribution<View, Context>` is generic over `Context`, so the desktop adapter could define `LeftPanelContext` and `RightPanelContext` separately (or make the context per-contribution via a generic on `DesktopPanelContribution`), keeping each side's factories honest.
