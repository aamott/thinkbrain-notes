- description: Cross-file interaction. `LeftPopout` line 32 and `RightPopout` line 28 call `getDesktopPanel(panel)` during render. `getDesktopPanel` (panelRegistry.tsx lines 225-229) throws `Desktop panel '${id}' is not registered.` when the id is absent. `DesktopShell` holds `leftPanel`/`rightPanel` in `useState<LeftPanel | null>` (lines 63-64) and `LeftPanel`/`RightPanel` are now `DesktopPanelId = BuiltInDesktopPanelId | (string & {})` (wide string — see wide-panel-id-type finding). Today the shell only sets these from activity-bar/title-bar clicks over registered contributions, so the throw path is not reached in normal use. However: (a) `desktopState` persistence restores `leftPanel` from `desktopState.explorerOpen ? "explorer" : null` (line 125) — currently safe, but if panel selection is ever persisted by id in the future, a stale id from a removed extension would throw in render and unmount the entire shell with no recovery; (b) the wide `LeftPanel` type means `setLeftPanel("exlorer")` compiles and would throw at runtime. A throw in a React render has no error boundary in this tree, so the whole app crashes. Recommendation: either narrow the shell state type (see wide-panel-id-type finding), or have the popouts call `desktopPanelRegistry.get(panel)` and render a safe "Panel not available" fallback when absent, reserving the loud throw for non-render call sites. At minimum, wrap the shell in an error boundary so a bad id degrades gracefully instead of crashing.
