- description: The acceptance criterion "Unit tests cover registration, lookup, and duplicate-id handling" is partially met, but several behaviors introduced by this story are untested:
  1. `getDesktopPanel(id)` (panelRegistry.tsx lines 225-229) throws `Desktop panel '${id}' is not registered.` for an unknown id — this fail-loudly path is NOT tested. The test only asserts `desktopPanelRegistry.get("missing")` returns `undefined` (line 77). The popout rendering test (lines 104-121) only checks the active panel's markup; it does not verify that an inactive `keepMounted` panel (e.g. `outline` while `backlinks` is active) stays mounted, or that a non-`keepMounted` inactive panel (e.g. `search`) is unmounted. This is the core lifecycle behavior the registry introduces.

  4. `data-panel-available` reflecting `availability` is not asserted (the attribute is emitted but, as noted in a separate finding, never consumed — but if it is intended as an a11y/testing hook it should be pinned).
  5. No test renders an *available* real panel (e.g. `outline` or `properties`) through the popout to confirm the factory output appears; only unavailable panels (`tags`, `backlinks`) are rendered.
