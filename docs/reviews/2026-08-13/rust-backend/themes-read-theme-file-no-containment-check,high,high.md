- name: `read_theme_file` accepts any absolute path with no containment check — reads arbitrary files from app-data
- file: /media/adam/extex/projects/thinkbrain-notes/apps/desktop/src-tauri/src/commands/themes.rs
- lines: 199-225
- description: `read_theme_file(path: String)` (lines 199-225) takes an arbitrary absolute path, checks only `path.exists()`, and reads it with `std::fs::read_to_string`. There is **no** check that the path lives under the themes directory (`<app_data_dir>/themes/`). The docstring (lines 199-209) acknowledges this: "This bypasses the Tauri FS plugin's scope restrictions (which prevent reading from the app-data directory) by using `std::fs` directly." But bypassing the *Tauri* scope and bypassing *all* containment are different things: a compromised or buggy renderer can call `read_theme_file` with `/etc/passwd` or `C:\Windows\System32\config\SAM` and receive the contents.

  The frontend `list_themes` command returns absolute paths (line 189: `path: path.to_string_lossy().into_owned()`), so the renderer legitimately has paths under the themes dir — but the renderer is a webview, and any XSS or extension code running in the renderer can call this command with any path. The `extensions.rs` module does the right thing (`resolve_extension_file` canonicalizes both the directory and the file and prefix-checks, lines 73-125); `themes.rs` should do the same: resolve `themes_dir(&app)` (it has access via the `app` parameter — but note `read_theme_file` does *not* take `app`, only `path`), canonicalize the requested path, and verify it starts with the canonical themes dir.

  Fix requires adding `app: tauri::AppHandle` to the `read_theme_file` signature (it currently only takes `path`), then `themes_dir(&app)?` and a `canonical_path.starts_with(&canonical_themes_dir)` check. The frontend call site (`native/commands.ts`) already passes the absolute path returned by `list_themes`, so legitimate calls keep working; only out-of-scope paths get rejected.
- verification: read themes.rs:199-225 — only `path.exists()` is checked, no `starts_with` containment. Compared to extensions.rs:99-115 which canonicalizes and prefix-checks. `read_theme_file` is registered in `mod.rs:69` and exposed to the renderer.
