- description: `disable_dmabuf_renderer_on_nvidia` runs inside `run()` and calls `std::env::set_var("WEBKIT_DISABLE_DMABUF_RENDERER", "1")`. As of Rust 1.80 `std::env::set_var` is `unsafe` because mutating the environment after threads exist is a data race (the process may already have spawned helper threads by the time `run()` is reached, and Tauri/WebKitGTK spawn threads early). The function is also called only for its side effect and silently does nothing if `/proc/driver/nvidia/version` is absent — fine for the NVIDIA case, but the env mutation should be wrapped in `unsafe` and ideally performed before any Tauri/WebKitGTK code runs (e.g. at the very top of `main`), or replaced with a documented "set this in your shell" note. Not a security bug; flagged because the build will break on a future toolchain and because the placement is racy in principle.
- verification: read lib.rs lines 23-36; confirmed `set_var` is called from `run()` after `tauri::Builder` setup begins, with no `unsafe` block.
- resolution: Deferred — high cost, low reward. Crate is edition 2021, so `set_var` is not yet `unsafe` (no build break). The placement-race claim in the finding is inaccurate: `disable_dmabuf_renderer_on_nvidia()` runs at lib.rs:36, *before* `tauri::Builder::default()` at line 38, so no Tauri/WebKitGTK threads exist yet. The only real concern is a future upgrade to edition 2024, which would require wrapping the call in `unsafe { }` — handle that when the edition bump happens.
