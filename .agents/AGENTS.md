# Project Overview: Note App Workspace

This file is automatically loaded by all AI agents operating in this workspace. **You MUST adhere to these architectural rules and principles at all times.**

## Vision
Build an open, privacy-first knowledge workspace inspired by Obsidian and VS Code for desktop and mobile. 
- **Fast**: Fast startup, minimal memory usage, lazy loading.
- **Local-first**: Everything works offline. Internet features are optional.
- **Markdown-first**: Markdown files are the single source of truth. No database lock-in.
- **Extensible**: Everything should be replaceable through the extension API.
- **AI-native**: AI should enhance workflows, but is optional. Local models are supported.
- **Git-friendly**: Projects are normal folders, files are normal Markdown.
- **Privacy**: The user owns their data. No telemetry, no vendor lock-in.

## Architecture & Technology Constraints
- **Frontend**: React, TypeScript, Vite. State management via Zustand.
- **Desktop Shell**: Tauri (Rust backend).
- **Mobile Client**: React Native (via Expo) for Android/iOS.
- **Editor**: CodeMirror 6 with live markdown rendering as obsidian-like as possible.
- **Data Model**: Pure Markdown. Tasks are represented *only* as Markdown checkboxes (`- [ ]`). No proprietary task object databases.
- **Database**: SQLite with FTS5. The database is strictly an *ephemeral cache* generated by the indexer. It is NEVER the source of truth, and must be stored in the OS's `AppData` directory, not the user's vault.

## Non-Negotiable Rules
1. **User Data Separation**: Application data (settings, search index, cache) must NEVER be stored in the vault. The vault contains only Markdown files and attachments.
2. **"Bring Your Own Sync"**: The app has no cloud sync. Users rely on OneDrive/Syncthing/Git. Do not write code that assumes proprietary cloud backends.
3. **Hub and Spoke**: The `packages/` (Shared Core) contains all business logic and must *never* depend on UI implementations. Platform-specific apps (`apps/desktop`, `apps/mobile`) implement the adapters.
4. **Permissions**: V1 Extensions use a strict capability-based sandbox (Install from URL/File). No unrestricted filesystem access.

Before implementing any feature, ensure you have read the detailed architectural blueprints in the `plans/` directory.
