# Plans compaction policy (temporary — delete after the pass)

Goal: plans/ is read by agents and the owner when picking work, not as history.
Make it short and truthful. Git history keeps everything deleted here.

Filename grammar (unchanged): `[NN-]status-name[-urgency]-difficulty.md`,
status in {pending, wip, done, cancelled, blocked}. Refer to stories by slug
only (never by filename) inside plan text.

## Rules

1. **Done stories → delete the file**, after folding it into its epic folder's
   `done-summary.md` as ONE bullet: `- \`slug\` — what shipped and any lasting
   decision/caveat` (≤ 2 lines). Create `done-summary.md` if the folder lacks
   one (title `# <Epic> — Completed Work`, one-paragraph intro, grouped bullets).
   Keep existing summaries but tighten them: no dates/worklogs/evidence trails,
   no test counts, no "verified on X" unless it is a caveat that still matters.
2. **Cancelled stories → delete**, leaving one bullet under a `## Cancelled`
   heading in `done-summary.md` with the reason (≤ 1 line).
3. **Fully done epics** (top-level `done-<epic>-*.md` and/or every story done):
   compact to a single top-level epic file of ≤ 40 lines (goal, shipped list by
   slug, lasting decisions, known gaps). Delete the epic's folder once its
   content is folded in (move `assets/` only if referenced by a remaining
   plan — otherwise delete them too).
4. **Open (pending/wip/blocked) stories stay.** Trim only obvious bloat:
   worklogs, repeated context already in the epic, long evidence sections,
   resolved investigation notes. Keep: context needed to start, acceptance
   checkboxes, open questions, design decisions. Target ≤ 60 lines; never drop
   an unchecked acceptance item or open question.
5. **Top-level wip/pending epic files**: keep goal, scope, architecture
   decisions, and a status list (one line per story slug with ✅/⬜). Remove
   long narrative and anything duplicated in `done-summary.md`. Target ≤ 80 lines.
6. **Status must match reality.** If a story's checkboxes are all ticked but
   the filename says wip/pending, or a wip epic has no open stories left, fix
   the filename (done) and fold it per rule 1/3. If unsure, leave it and list
   it in your report — don't guess.
7. **References:** before deleting or renaming any file, grep the whole repo
   (code comments, docs/, AGENTS.md files, other plans) for its path. Update
   path references to point at the surviving file (e.g. the epic's
   `done-summary.md` or the epic file). Do NOT edit any AGENTS.md except
   `## File Map` lines. Code-comment path fixes are allowed (change only the
   path text).
8. Don't touch `plans/app-vision.md` or `docs/`, except path references (rule 7).
9. Use `git mv` / `git rm` so renames show in history. Do not commit.
