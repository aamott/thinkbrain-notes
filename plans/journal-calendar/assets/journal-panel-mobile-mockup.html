The list, full screen

The popout fills the screen at phone widths, and everything above it belongs to the app shell — the title, the close affordance, the way back. The journal contributes no navigation of its own, no bottom bar, no back gesture. The dashed outline below marks what the journal does not own.

shell-owned chrome, drawn for context only

The one question — how tall is a row?

D55 sizes rows by the popout's own width, and a full-screen phone popout is 390 px — the widest tier, whose row is a single 26 px line. That is a comfortable reading row and an uncomfortable tapping one: it is roughly half the 44 px minimum, and every row here opens a file.

So the rows above use the two-line form at a 44 px minimum height. Seven fit on screen, which is close to M‑1's nine and still reads as a dense list rather than a set of cards.

Recommended: touch decides the row height on a phone, width decides it on a desktop

The alternative is honouring the width tier literally and accepting 26 px targets. D31's formal touch-target audit is deferred, so nothing forces the issue — which is exactly why it is worth deciding on purpose now rather than inheriting it by accident.

Editing metadata

On a desktop the metadata widget expands in place. On a phone it cannot: multi-select alone needs more room than a dateline has, and D4 lets a user define as many fields as they like. So the dateline stays exactly what it is — a summary you tap — and the editing moves to a sheet.

The sheet is the only new component in the journal, and it is confined to metadata editing. It does not replace the popout, does not host navigation, and closes back to the note the user was already reading.

Behaviour the sheet owes

  • Focus is trapped while it is open, and returns to the dateline control that opened it.
  • It announces itself as a dialog named for the entry's date, so a screen-reader user knows what they are editing.
  • Dismiss by swipe, scrim tap, or the shell's back — all three land in the same place, the note.
  • Values save as they change, the same as the desktop widget; `Done` closes rather than commits, so nothing is lost to a stray dismissal.
