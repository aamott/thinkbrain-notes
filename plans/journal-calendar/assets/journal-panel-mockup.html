The whole surface

The popout is the file explorer's sibling — dense, flat, unsentimental. The editor is a page: a measured column with the metadata widget set as its dateline. The contrast between the two is the design.

Both themes below are the app's own, unmodified. The dark theme's forest green and the light theme's purple come from the token file; the journal adds nothing.

The header

Actions, then search, then the filter row. New entry is the only filled control in the panel — Today and Open calendar sit beside it as outlined buttons, present without competing. Overflow stays where every other panel keeps it, in the chrome row.

One filled control per surface is what makes it read as the action rather than one of three. Today and Open calendar are used often enough to be one click away and not often enough to be coloured.

Search sits directly above the filter row and the list because those three are one thing: what you typed, what you filtered by, and what came back. Putting the actions between them separates the query from its own result.

The list

Flat, never indented. Year and month headers are told apart by weight, size, case and ground — the year is uppercase and tracked on a filled band, the month is sentence case on a hairline. Neither is inset, so a row's left edge is the same everywhere in the list and the eye can run straight down it through ten years of entries.

Undated files are pinned above everything as a collapsed category with a count. They are not an error and are not styled as one: no warning colour, no icon, just a group whose name says what it is.

Row width tiers (D55, amended by D72)

The row responds to the popout's own width, not the window's. The shell's default is 288 px, which is the middle tier — so the two-line row is what most people will actually see, and the one-line row appears only after someone widens the panel. The default stays where the shell puts it; a panel that resizes the shell to suit itself is a surprise, and one drag persists.

Losing the preview would leave a column of bare dates, which is the one thing a date-named-file list already does badly and the reason this list exists at all. So it stays at every width, and there is no setting for it: the journal ships exactly the four settings D64 approved, and a fifth would be a new decision for a preference nobody has asked for yet. If it turns out people want the dense date-only column, that's a cheap setting to add later — the row already knows how to render both.

Filters, and saying so

An active filter has to be impossible to miss — a count badge, a chip row, and a plain "showing N of M" line, all three (D16). A single muted indicator is the failure mode where someone concludes their entries are gone.

The filter control sits hard right, with the count line filling the space to its left, so the row reads as one statement — this many, because of this control — rather than two things that happen to share a line.

The day the calendar sends over is a chip like any other, dismissible on its own; letting it go clears the calendar's selection in the same movement (D60).

The metadata widget

Collapsed by default and set as the page's dateline, so the summary and the affordance are the same object. With no values it is just the date — no placeholder, no empty chips, no "not set" (D54). The most common entry is the one with nothing recorded, and it should look finished, not unfilled.

Why the year is back — and what it caught

Friday, August 7, 2026, long form, year included. The year isn't redundant with the filename, because the filename is the thing that can be lost: rename a file by accident and the frontmatter date is the only surviving record of when the entry was written. A date you can read on the page is a date you can restore from.

Which points at a gap. The filename always wins (D20), and the frontmatter date is already checked against it — the parser emits a mismatch warning today — but nothing was ever specified to show that warning. So the backup date could quietly disagree with the filename forever and the page would look fine. Plate D is the fix: when the two disagree, the dateline says so, names both dates, and says which one is being used. Non-blocking, and it never rewrites the file.

What changed from v1

  • D71 — action emphasis. New entry is a primary button with Today and Open calendar beside it as outlined buttons; it is the only filled control in the panel. The chrome row keeps only •••. Amends the focus order proposed in D31.
  • D75 — search stays below the actions, directly above the filter row and the list, so the query and its results read as one group.
  • D72 — the preview is never dropped. D55's <260px tier is withdrawn; at every width the first line stays and simply gets fewer words. No setting is added — D64's four stand.
  • D73 — the filter control is right-aligned, with the "showing N of M" count filling the row to its left.
  • D74 — the dateline keeps the year, long form. Because the frontmatter date is the backup record, a filename/frontmatter mismatch now surfaces in the dateline (plate D) instead of staying silent.
