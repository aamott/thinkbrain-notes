Why today

What it looks like now

To record a mood on an entry you have to type a JSON array, with the right keys, in the right shape, quoted correctly. Get a comma wrong and it refuses to save — correctly, but without telling you where. There is no Add button, because there is nothing to add to: it is a text box with a spell-checker's manners.

D49 fixed how these are stored — one string setting holding a JSON array, rendered by a custom control. It said nothing about how they are edited, and the custom control is exactly the seam that lets the editing surface be a form. Everything below writes the same JSON to the same setting.

The list, and adding to it

The whole control is a list of what you record, and a button to add to it. A field is three questions: what to call it, what kind of thing it is, and — for the two list kinds — what the choices are.

D48 reserved
D49 key rules

The key, and when it bites

Every field has a key — the word that actually appears in your note's frontmatter. It has rules: lowercase, no spaces, and it can't be one the app already uses for something else. Nobody should have to know any of that, so the key is derived from the name and shown as small print. Click Change only if you care.

D50 never repair

Removing a field doesn't remove anything you wrote

D50 says the app reads leniently and never repairs. So removing a field stops offering it on new entries — it does not go into 300 notes and delete a line. That is a good decision and a surprising one, so the confirmation says it out loud rather than leaving you to find out.

D34

Three things to decide

1 · Do the kind names land?

Pick one from a list · Pick several from a list · A number · A few words, each with an example beside it. These are the words a first-time user reads, so they matter more than anything else on the page.

Recommendation — ship these words, and change them the moment they trip somebody up

2 · Should the key be visible by default?

The mockup shows Saved in your notes as mood as small print under the name, always. The alternative is hiding it until you click Change.

It is one more thing on screen for someone who will never open a .md file in a text editor. But this is a local-first app whose whole promise is that your notes are your files — quietly writing a word into them and not saying which word seems like the wrong kind of tidy.

Recommendation — always visible, small

3 · Starter presets: yes or no?

The fastest possible setup is a button that creates Mood, Energy and Context for you. It is also the app shipping a mood vocabulary, which is exactly what D4 forbids — the values are meant to be yours, with no scale we invented.

My read is that the examples beside each kind are a hint, while a one-tap preset is a taxonomy. But this is your product call, and if you want the presets it becomes a new decision that narrows D4 rather than something I quietly slip past it.

Recommendation — no presets; keep the examples
