What to show when a note changes on disk while you are editing it

The watcher now tells the app about writes it did not make. A tab with no unsaved edits just reloads, silently, and needs nothing on screen. A tab holding unsaved edits is the case that needs you: two versions of the note exist, and only you know which one matters.

Three ways to raise it, in the app's real tokens. Pick one and I will build it — the rest of the story is already in.

Open questions — answer with the pick

Should “Keep mine” write my version to disk straight away?

My answer: no — it dismisses, and saving stays a separate deliberate act. Overwriting someone else's work should take the same keystroke it always takes, not be a side effect of clearing a notice.

Worth knowing either way: write_markdown_file overwrites blind, so a later save from this tab replaces the newer file whichever button you press here. Closing that needs a Rust change and is written up as its own story.

Should there be a third button that shows the two versions side by side?

My answer: not yet. It needs a diff view, and the git epic already has one planned (inline_diff_viewer). Better to reuse that when it exists than to build a second one here.

Should a silent reload say anything at all?

My answer: no. A tab with no unsaved edits was showing a copy of the file; now it shows the file. That is what the tab is for, and a notice for it would fire on every git pull.
